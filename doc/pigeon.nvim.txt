*pigeon.nvim*

pigeon

Create Agents, show them in a Neovim Terminal, and deliver captured Messages to
the current Agent. See installation |aviary.nvim-installation| and requirements
|aviary.nvim-requirements|. Pigeon accepts content from weaver |weaver.nvim| or
your own Message construction.


==============================================================================
1. Usage                                                   *pigeon.nvim-usage*

*pigeon.nvim-api* *pigeon.pick()* *pigeon.show()* *pigeon.send()*
*pigeon.status()*

>lua
    local aviary = require("aviary")
    local pigeon = aviary.pigeon
    local Message = require("aviary.shared.message")
    pigeon.pick()   -- choose an existing Agent or create another instance
    pigeon.show()   -- reopen/focus this Neovim's Terminal; pick when no Agent is attached
    pigeon.send(Message.reference("/project/src/a.lua", 12, 15))
    pigeon.status() -- report the Terminal's current Agent
<

Actions return nothing. Failures notify once; picker cancellation is quiet and
preserves the current Agent. Requests are never automatically replayed. `send`
requires a Terminal: call `pick()` or `show()` first. Weaver sends to the same
Terminal, including while its window is hidden. Sending never focuses the
Terminal or presses Enter. Empty text does nothing.

The built-in close action, bound to `<C-.>` by default, closes only the Neovim
window. `show()` reopens it in Terminal mode. The attach client and buffer
remain alive while hidden.

2. Exporting and selection               *pigeon.nvim-exporting-and-selection*

There is one Terminal per Neovim, and it has one current Agent. `pick()` lists
existing Agents and creation choices in `vim.ui.select`; a single candidate is
still passed to the configured picker. Entries begin with ` <tool>` to
create an instance or ` <tool> <launch cwd> [<session>]` to reuse an Agent.
The current Agent appears first with `[current]`. Discovery includes only
Pigeon Agents on Neovim’s host tmux server whose tool names exist in local
configuration. Renaming a tmux window does not change an Agent’s identity or
formatter.

Each Agent has its own persistent tmux session with one agent window. This
Neovim’s client attaches directly to that session; no temporary View session
is created. Switching Agents reuses the Terminal buffer, job and client: the
existing tmux client moves to the new Agent session. Different editors choose
independently, and multiple editors attached to the same Agent share its input
and output. Terminal size follows your tmux `window-size` policy; Pigeon does
not override it.

Closing the window keeps the buffer, job and client attached. Exiting Neovim
detaches that editor’s client and preserves the Agent. Exiting an Agent
removes its only window and session, ending its attached clients; their
`TermClose` events close the corresponding Neovim Terminals. Closing the tmux
server stops all Agents.

Configure action keymaps and the float:

>lua
    require("aviary").setup({
      pigeon = {
        keymaps = { close = { "<C-.>" } },
        view = { width = 0.9, height = 0.9, border = "rounded" },
      },
    })
<

`keymaps` maps action names to lists of Neovim keys. Each list replaces its
defaults, and `{}` disables that action’s keys. `actions` maps action names
to handlers and merges over built-ins; the built-in `close` closes the current
window. Handlers take no arguments, and every mapped custom action needs one.
Keymaps and actions are resolved when the Terminal is created, installed
buffer-locally in Normal and Terminal modes, and later setup changes apply to
new Terminals.

Width and height are fractions in `(0, 1]` or integer cell counts greater than
one. Sizes refer to the float’s content and are clamped to the available
editor area. Border accepts `none`, `single`, `double`, `rounded`, `solid` or
`shadow`. The float fixes its Terminal buffer with `'winfixbuf'`; switching it
to another buffer is unsupported. Width, height and border apply when a window
is opened or reopened. A visible window keeps its size when the editor is
resized; hiding and showing it recalculates the geometry.

Pigeon uses tmux’s default socket and your existing server configuration, and
starts no private server. Neovim must run inside tmux with `TMUX` set. Each
Agent session sets `destroy-unattached=off`, `detach-on-destroy=on`,
`status=off`, `prefix=None` and `prefix2=None`; its window sets
`remain-on-exit=off` and `pane-border-status=off`. These options keep the Agent
alive without clients, ensure an exiting Agent ends its clients instead of
moving them elsewhere, and remove the pane border. No global tmux key tables,
hooks or key bindings are installed.

Keyboard input passes through Neovim’s terminal handling before reaching the
nested tmux client. Pigeon adds no Shift/Alt+Enter correction mappings; these
keys follow Neovim and your own configuration. The Terminal buffer filetype is
`aviary-pigeon` for user customization. Outer tmux bindings may consume keys
before Neovim sees them.

3. Tools and formatting                     *pigeon.nvim-tools-and-formatting*

Built-ins are `codex` and `claude`. Partial overrides preserve their other
fields; custom tools require a nonempty `command` argv list. Commands execute
directly, without shell interpretation. The editor’s cwd is captured when
creation begins.

>lua
    require("aviary").setup({
      pigeon = {
        tools = {
          codex = { command = { "codex", "--model", "my-model" } },
          custom = {
            command = { "my-cli" },
            format = function(path, first, last)
              return path .. (first and ":" .. first or "")
                .. (first and last and last ~= first and "-" .. last or "")
            end,
          },
        },
      },
    })
<

Each send uses the Terminal’s current Agent. That Agent supplies its launch
cwd and the current local same-named tool formatter. Paths inside the launch
cwd are relative; others stay absolute. A tool’s `format` overrides
`pigeon.format`. Codex uses the default `file :L12-15`; Claude uses
`@file#L12-15`, quoting unusual paths.

Pigeon changes the current Agent only after `pick()` or `show()` successfully
selects or creates one. Moving this editor’s tmux client outside Pigeon is
not a supported way to change Agents; the Agent session disables its prefix and
status line so normal key input cannot move the client by accident.

`format(path, start_row?, end_row?)` receives raw 1-based inclusive rows; nil
start means the whole file. It must return a nonempty string. The complete
Message is evaluated before any delivery; invalid references or formatter
errors send nothing. Updating local formatters affects the next send without
changing a running Agent’s argv or launch cwd. Removing its local tool
definition makes sending fail and hides it from discovery, leaving the Agent
running.

Delivery uses tmux bracketed paste when the Agent supports it, preserving raw
newlines. Success acknowledges the paste request, not processing by the Agent.
A failed evaluation or delivery reports once, preserves the current Agent and
ends the request. There is no fallback to an earlier Agent.

4. Messages                                             *pigeon.nvim-messages*

The shared Message module <../lua/aviary/shared/message.lua>, loaded through
`require("aviary.shared.message")`, provides `text(string)`,
`reference(absolute_path, start_row?, end_row?)` and `join(delimiter,
children)`. These capture content; reference spelling waits for the destination
context. An empty filename represents an unnamed source and fails evaluation.
Keep borrowed trees unchanged until synchronous `send` returns. Shared Message
has no built-in reference syntax.

5. Health and migration                     *pigeon.nvim-health-and-migration*

Run `:checkhealth aviary.pigeon` for tmux version/context and tool executables.
Health is read-only. Setup merges and validates configuration without acquiring
resources or checking executable availability. Unknown fields are rejected;
`pigeon.setup(opts)` returns `false, reason` and preserves running
configuration on failure. See setup scope |aviary.nvim-installation|.

Clipboard support and the old nested `pigeon.backend` configuration are
removed; only the `tmux` backend is available. Replace `backend.tmux` display
options with `pigeon.view` for size and border and with `pigeon.keymaps.close`
for the key: use `0.9` instead of `"90%"`, `80` instead of `"80"`, and Neovim
key notation such as `{ "<C-.>" }` instead of tmux’s `"C-."`. Select an Agent
before sending. Sessions created by the previous receiver/View model are not
migrated into the new discovery format; create fresh Agents through `pick()`.
Old native floating panes and their shared `aviary-pigeon` key table are not
managed by this version. Internal `pigeon.backends.*` paths are removed.
