*pigeon.nvim*

pigeon

Create Agents, show them in a Neovim Terminal, and run actions that send
references or prompts to the current Agent. See installation
|aviary.nvim-installation| and requirements |aviary.nvim-requirements|.


==============================================================================
1. Usage                                                   *pigeon.nvim-usage*

*pigeon.nvim-api* *pigeon.pick()* *pigeon.show()* *pigeon.status()*

>lua
    local aviary = require("aviary")
    local pigeon = aviary.pigeon
    pigeon.pick()   -- choose an existing Agent or create another instance
    pigeon.show()   -- reopen/focus this Neovim's Terminal; pick when no Agent is attached
    pigeon.status() -- report the Terminal's current Agent
<

`show()` and `pick()` capture the current editor reference before changing
focus. Actions run from the Terminal and receive that reference. There is no
public send function: compose and deliver content inside an action
|pigeon.nvim-actions|. Actions return nothing. Failures notify once; picker
cancellation is quiet and preserves the current Agent. Requests are never
automatically replayed. Empty text does nothing.

The built-in close action, bound to `<C-.>` by default, closes only the Neovim
window. `show()` reopens it in Terminal mode. The attach client and buffer
remain alive while hidden.

2. Actions                                               *pigeon.nvim-actions*

`keymaps` maps action names to lists of Neovim keys. Each list replaces its
defaults, and `{}` disables that action’s keys. `actions` maps action names
to handlers and merges over built-ins. Handlers receive the current Agent and
the captured reference:

>lua
    ---@param agent aviary.pigeon.Agent
    ---@param reference aviary.pigeon.Reference
<

Keymaps and actions are resolved when the Terminal is created, installed
buffer-locally in Normal and Terminal modes, and later setup changes apply to
new Terminals. Every mapped action needs a handler; built-ins are available by
name.

Built-ins are `close` and `prompt`. `close` closes the current window. `prompt`
selects a named template and sends it; it has no default keys. Send actions
have no default keys so they cannot conflict with an Agent’s own input;
configure the ones you want:

>lua
    require("aviary").setup({
      pigeon = {
        keymaps = {
          close = { "<C-.>" },
          prompt = { "<C-p>" },
        },
      },
    })
<


SENDING CONTENT                          *pigeon.nvim-actions-sending-content*

`agent:send(text)` pastes raw text without focusing or submitting. To render a
file reference, use `agent:eval(reference)` first. A reference is a plain
table:

>lua
    ---@class aviary.pigeon.Reference
    ---@field path string
    ---@field start_row? integer
    ---@field end_row? integer
<

`start_row` and `end_row` are 1-based inclusive rows; omit both for a
whole-file reference and omit `end_row` for a single row. `Agent:eval` resolves
the path relative to the Agent’s launch cwd and calls the Agent’s current
formatter. It raises when the path is empty or the formatter returns no text.
Render every reference before sending so a failure cannot deliver partial
content.

>lua
    local texts = {}
    for _, path in ipairs(paths) do
      texts[#texts + 1] = agent:eval({ path = path })
    end
    agent:send(table.concat(texts, "\n"))
<


FILES AND BUFFERS ACTIONS      *pigeon.nvim-actions-files-and-buffers-actions*

Pigeon ships no picker and no built-in `files` or `buffers` action. Define the
action with whichever picker you use. The picker owns discovery, previews,
selection rules and its own cleanup; deliver after its UI has closed.

Snacks example:

>lua
    local function send_paths(agent, paths)
      local texts = {}
      for _, path in ipairs(paths) do
        texts[#texts + 1] = agent:eval({ path = path })
      end
      agent:send(table.concat(texts, "\n"))
    end

    require("aviary").setup({
      pigeon = {
        keymaps = { files = { "<C-f>" } },
        actions = {
          files = function(agent)
            local picker = require("snacks").picker
            picker.pick("files", {
              confirm = function(selected)
                local paths = {}
                for _, item in ipairs(selected:selected({ fallback = true })) do
                  local path = picker.util.path(item)
                  if path then
                    paths[#paths + 1] = path
                  end
                end
                selected:close()
                vim.schedule(function()
                  send_paths(agent, paths)
                end)
              end,
            })
          end,
        },
      },
    })
<

Other pickers use the same contract: select absolute paths in confirmation
order, close their UI, then call `agent:eval` and `agent:send`. The action owns
asynchronous error handling; wrap delivery yourself if the picker can fail
after it closes.

3. References                                         *pigeon.nvim-references*

`show()` and `pick()` capture a reference before focusing the Terminal. In
Visual mode the reference contains the inclusive whole-line range and Pigeon
exits Visual; otherwise it contains the cursor row with `end_row` omitted. The
path is snapshotted at capture time, so later renames or edits do not change an
already captured reference; show the Terminal again to refresh it. Capturing
does not open or validate the file.

Invocations from the Terminal itself do not replace the reference. Actions run
from the Terminal therefore always see the last reference captured from an
editor window. The reference is plain data, not a buffer handle: closing the
source window does not invalidate it.

Action handlers may construct whole-file references and references to other
paths. `Agent:eval` only renders them; it does not read or modify the source.

4. Prompts                                               *pigeon.nvim-prompts*

The built-in `prompt` action uses the captured reference and a named template.
Bind it in the Terminal:

>lua
    require("aviary").setup({
      pigeon = {
        keymaps = { prompt = { "<C-p>" } },
      },
    })
<

Capture a reference first. For a Visual range, call `show()` from Visual mode;
for a normal-mode mapping, the cursor line is captured. See references
|pigeon.nvim-references| for capture timing.

Templates and resolvers merge with Pigeon’s defaults:

>lua
    require("aviary").setup({
      pigeon = {
        prompts = {
          ["{file}"] = "{file} ",
          ["{line}"] = "{line} ",
          review = "Review {line} for bugs.",
        },
        resolvers = {
          rows = function(_, reference)
            local last = reference.end_row or reference.start_row or 0
            return tostring(last - (reference.start_row or 0) + 1)
          end,
        },
      },
    })
<

The built-in resolvers are `file` (a whole-file reference) and `line` (the
captured file and row or range). A resolver receives the Agent and the
reference, and returns a string:

>lua
    ---@alias aviary.pigeon.Resolver fun(agent: aviary.pigeon.Agent, reference: aviary.pigeon.Reference): string
<

Resolvers can render references with `agent:eval` and may return any text,
including composites. Names in templates use letters, digits and underscores.
Only the selected template is expanded, once per occurrence, in token order.
Tokens without a resolver are sent verbatim; literal spacing, punctuation,
percent signs and newlines are preserved. The template and resolvers are
captured before the selector opens; setup changes apply to the next invocation.
The selector lists the configured prompt names. Cancellation calls no resolvers
and sends nothing. Resolver and rendering errors notify once without delivering
partial content.

Prompt capture exits Visual mode before changing focus. Use a Lua callback or
`<Cmd>` Visual mapping to retain the active selection until `show()` or the
action runs.

5. Agents and display                         *pigeon.nvim-agents-and-display*

There is one Terminal per Neovim, and it has one current Agent. `pick()` lists
existing Agents and creation choices in `vim.ui.select`; a single candidate is
still passed to the configured picker. Entries begin with ` <tool>` to
create an instance or ` <tool> <launch cwd> [<session>]` to reuse an Agent.
The current Agent appears first with `[current]`. Discovery includes only
Pigeon Agents on Neovim’s host tmux server whose tool names exist in local
configuration. Renaming a tmux window does not change an Agent’s identity or
formatter.

Each Agent has its own persistent tmux session with one agent window. This
Neovim’s client attaches directly to that session; no temporary View session
is created. Switching Agents reuses the Terminal buffer, job and client: the
existing tmux client moves to the new Agent session. Different editors choose
independently, and multiple editors attached to the same Agent share its input
and output. Terminal size follows your tmux `window-size` policy; Pigeon does
not override it.

Closing the window keeps the buffer, job and client attached. Exiting Neovim
detaches that editor’s client and preserves the Agent. Exiting an Agent
removes its only window and session, ending its attached clients; their
`TermClose` events close the corresponding Neovim Terminals. Closing the tmux
server stops all Agents.

Configure the float:

>lua
    require("aviary").setup({
      pigeon = {
        view = { width = 0.9, height = 0.9, border = "rounded" },
      },
    })
<

Width and height are fractions in `(0, 1]` or integer cell counts greater than
one. Sizes refer to the float’s content and are clamped to the available
editor area. Border accepts `none`, `single`, `double`, `rounded`, `solid` or
`shadow`. The float fixes its Terminal buffer with `'winfixbuf'`; switching it
to another buffer is unsupported. Width, height and border apply when a window
is opened or reopened. A visible window keeps its size when the editor is
resized; hiding and showing it recalculates the geometry.

Pigeon uses tmux’s default socket and your existing server configuration, and
starts no private server. Neovim must run inside tmux with `TMUX` set. Each
Agent session sets `destroy-unattached=off`, `detach-on-destroy=on`,
`status=off`, `prefix=None` and `prefix2=None`; its window sets
`remain-on-exit=off` and `pane-border-status=off`. These options keep the Agent
alive without clients, ensure an exiting Agent ends its clients instead of
moving them elsewhere, and remove the pane border. No global tmux key tables,
hooks or key bindings are installed.

Keyboard input passes through Neovim’s terminal handling before reaching the
nested tmux client. Pigeon installs no modified-Enter mappings by default;
these keys follow Neovim and your own configuration. A custom action runs in
the Terminal buffer and can forward the CSI-u sequence through that buffer’s
terminal job when your outer terminal reports Shift+Enter distinctly:

>lua
    require("aviary").setup({
      pigeon = {
        keymaps = { shift_enter = { "<S-CR>" } },
        actions = {
          shift_enter = function()
            vim.api.nvim_chan_send(vim.b.terminal_job_id, "\27[13;2u")
          end,
        },
      },
    })
<

The Terminal buffer filetype is `aviary-pigeon` for user customization. Outer
tmux bindings may consume keys before Neovim sees them.

6. Tools and formatting                     *pigeon.nvim-tools-and-formatting*

Built-ins are `codex` and `claude`. Partial overrides preserve their other
fields; custom tools require a nonempty `command` argv list. Commands execute
directly, without shell interpretation. The editor’s cwd is captured when
creation begins.

>lua
    require("aviary").setup({
      pigeon = {
        tools = {
          codex = { command = { "codex", "--model", "my-model" } },
          custom = {
            command = { "my-cli" },
            format = function(path, first, last)
              return path .. (first and ":" .. first or "")
                .. (first and last and last ~= first and "-" .. last or "")
            end,
          },
        },
      },
    })
<

Each reference is rendered using the Terminal’s current Agent. That Agent
supplies its launch cwd and the current local same-named tool formatter. Paths
inside the launch cwd are relative; others stay absolute. A tool’s `format`
overrides `pigeon.format`. Codex uses the default `file :L12-15`; Claude uses
`@file#L12-15`, quoting unusual paths.

Pigeon changes the current Agent only after `pick()` or `show()` successfully
selects or creates one. Moving this editor’s tmux client outside Pigeon is
not a supported way to change Agents; the Agent session disables its prefix and
status line so normal key input cannot move the client by accident.

`format(path, start_row?, end_row?)` receives raw 1-based inclusive rows; nil
start means the whole file. It must return a nonempty string. Updating local
formatters affects the next render without changing a running Agent’s argv or
launch cwd. Removing its local tool definition makes rendering fail and hides
it from discovery, leaving the Agent running.

Delivery uses tmux bracketed paste when the Agent supports it, preserving raw
newlines. Success acknowledges the paste request, not processing by the Agent.
A failed evaluation or delivery reports once, preserves the current Agent and
ends the request. There is no fallback to an earlier Agent.

7. Health and migration                     *pigeon.nvim-health-and-migration*

Run `:checkhealth aviary.pigeon` for tmux version/context and tool executables.
Health is read-only. Setup merges and validates configuration without acquiring
resources or checking executable availability. Unknown fields are rejected;
`pigeon.setup(opts)` returns `false, reason` and preserves running
configuration on failure. See setup scope |aviary.nvim-installation|.

Weaver, its text action, the shared Message tree and the built-in picker
configuration are removed. Use Pigeon actions instead: `prompt` is built in,
and files/buffers are user actions for your picker. Raw text can be pasted with
your editor or agent, or sent from a custom action with `agent:send`. There is
no public `pigeon.send`; compose content in actions. References are plain `{
path, start_row?, end_row? }` tables rendered with `agent:eval`. Clipboard
support and the old nested `pigeon.backend` configuration remain removed; only
the `tmux` backend is available. Sessions created by the previous receiver/View
model are not migrated into the new discovery format; create fresh Agents
through `pick()`.
